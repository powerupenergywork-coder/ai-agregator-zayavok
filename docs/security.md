# Как мы тестируем безопасность

Многослойно — снизу дёшево и постоянно, сверху дорого и редко. LLM-пентест не
основа, а верхний слой по случаю.

## Слой 1 — бесплатно, на каждый PR ([`security.yml`](../.github/workflows/security.yml))

Три проверки без LLM и без внешних лимитов, каждая падает сама:

- **npm audit** — уязвимые зависимости (порог `high`).
- **Semgrep** — статический анализ: инъекции, небезопасные паттерны Node/TS,
  захардкоженные секреты.
- **Gitleaks** — секреты в коде и во всей истории git.

Плюс **Dependabot** ([`dependabot.yml`](../.github/dependabot.yml)) — еженедельные
авто-PR на обновление пакетов и экшенов.

Это постоянная база. Ничего не стоит, отчёты (SARIF) — в артефактах прогона.

## Слой 2 — ревью по коду

Самый эффективный слой для нашей стадии, бесплатный. Каждое изменение в
чувствительных местах (авторизация, заказы, вебхуки, биллинг) читается глазами.
Так были найдены и закрыты реальные вещи, которые автосканеры не подтверждали:

- обход IP-allowlist через `X-Forwarded-For` в `kaspi-biller.controller.ts`;
- replay вебхука Tole (окно давности подписи);
- IDOR через перебираемый id заказа (перешли на неугадываемый `publicToken`).

Security-инварианты закреплены тестами (`apps/api/test/`): подпись вебхука,
идемпотентность платежей, лимиты OTP, разделение ролей.

## Слой 3 — LLM-пентест Strix ([`strix.yml`](../.github/workflows/strix.yml)), редко и вручную

Активный ИИ-пентест стенда как чёрного ящика. Запуск **ручной** (Actions →
strix-pentest → Run workflow), не на каждый PR: гоняет платную LLM и на дешёвых
аккаунтах упирается в лимиты провайдера. Запускать перед крупным релизом или
раз в квартал. Подробно — [strix-security.md](strix-security.md).

Когда Strix уже прогоняли, он подтвердил карту приоритетных зон KerekTap: IDOR
по заказам → телефоны клиентов, обход IP в `/api/kaspi/pay` → бесплатная
подписка, подпись и replay `/api/tole/webhook`, роли `/admin/*` и `/billing/*`,
троттлинг `/auth-otp/*`. Эти зоны и держим под особым присмотром в слое 2.

## Известный техдолг по зависимостям

Разобрано `npm audit` (сентябрь 2026):

- **multer** → поднят до 2.3.0 (через `overrides`, т.к. Nest тянул старый 2.0.2).
  Закрыл DoS при загрузке фото заказов и заодно снял обе Nest-уязвимости —
  они шли через тот же multer. **Сделано.**
- **next 14 → 16 + React 18 → 19** — **сделано.** Закрыло всё, что висело на
  ветке next 14: critical RCE в Image Optimization API, SSRF в Server Actions
  и rewrites, DoS, postcss. Миграция прошла чисто (клиентские компоненты,
  async-`params` уже были, нет middleware/route handlers/Radix): правок кода не
  потребовалось, 657 тестов API и рантайм веба зелёные. React 19 форсирован
  через `overrides` — иначе next тянул вложенный React 18.
- **lodash** — единственная оставшаяся high, в allowlist (`audit-ci.jsonc`):
  транзитив через `@nestjs/config`, напрямую не вызываем (`_.template` с
  недоверенным вводом у нас нет). Уйдёт с апгрейдом Nest (`@nestjs/config@12`
  тянет Nest 11 — отдельная задача, не срочная).

Порог CI — `high`, известные принятые исключения — в `audit-ci.jsonc` с
причиной у каждого. Так `deps` зелёный на известном и краснеет только на новом.

## Инфра-замечания на потом (из Semgrep p/default)

Набор правил `p/default` показал полезное по инфраструктуре, но топил сигнал по
коду, поэтому из CI его убрали. Не забыть разобрать отдельно:

- **nginx h2c smuggling** (`nginx/nginx.conf`) — проверить обработку `Upgrade`/
  `Connection` в проксировании; боевой конфиг живёт на сервере, правки — с
  осторожностью (общий nginx на 4 проекта).
- **Dockerfile без `USER`** (api, web) — контейнеры от root; за nginx риск
  низкий, но добавить непривилегированного пользователя стоит.
- **Пины экшенов по SHA** вместо `@v4` — supply-chain-гигиена; Dependabot и так
  следит за версиями экшенов.

Разовый повторный прогон `semgrep --config p/default` покажет этот список
целиком.

## Слой 4 — когда вырастем

Реальный оборот и клиентские данные → разовый пентест живыми людьми (Strix
One-time или профильная фирма), позже — bug bounty.

## Базовая гигиена (важнее любого сканера на нашей стадии)

- Секреты не в git (`.env` в `.gitignore`) — Gitleaks стережёт это в CI.
- HTTPS везде; вебхуки с криптоподписью, а не только по IP.
- Rate limiting включён (throttler, флуд-лимит бота).
- Зависимости обновляются (Dependabot).
