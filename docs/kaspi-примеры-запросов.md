# KerekTap — приём платежей Kaspi: готовые запросы и ответы

ТОО «Power Solutions Company», БИН 191240014214
Контакт по интеграции: +7 708 952 6570

Один адрес на обе команды, различаются параметром `command`:

```
https://kerektap.kz/api/kaspi/pay
```

Метод — GET. Ответ всегда HTTP 200; результат читается из поля `result`.
Формат по умолчанию XML; JSON доступен параметром `format=json`.

**Идентификатор платежа — номер счёта (8 цифр), а не телефон.** За исполнителя
часто платит бухгалтер, жена или сын с другого номера, поэтому поиск по
телефону плательщика нашёл бы не того человека.

---

## 1. CHECK — проверка счёта

Ничего не меняет, вызывается сколько угодно раз.

```
https://kerektap.kz/api/kaspi/pay?command=check&txn_id=123456789&account=27797236
```

### Ответ: счёт найден, можно платить

```xml
<?xml version="1.0" encoding="UTF-8"?>
<response>
  <txn_id>123456789</txn_id>
  <sum>10000.00</sum>
  <result>0</result>
  <fields>
    <field1 name="Исполнитель">ТЕСТ Kaspi — не рассылать</field1>
    <field2 name="Услуга">Подписка на 30 дней</field2>
  </fields>
  <comment>OK</comment>
</response>
```

`fields` показываем плательщику, чтобы он видел, за кого платит, и не ошибся
номером счёта.

### Ответ: счёт не найден

```xml
<response>
  <txn_id>123456789</txn_id>
  <result>1</result>
  <comment>Счёт не найден</comment>
</response>
```

### Ответ: счёт уже оплачен

```xml
<response>
  <txn_id>123456789</txn_id>
  <result>3</result>
  <comment>Счёт уже оплачен</comment>
</response>
```

### Ответ: счёт отменён или просрочен

```xml
<response>
  <txn_id>123456789</txn_id>
  <result>2</result>
  <comment>Срок оплаты счёта истёк</comment>
</response>
```

## 2. PAY — проведение платежа

```
https://kerektap.kz/api/kaspi/pay?command=pay&txn_id=123456789&account=34906842&sum=10000&txn_date=20260810134500
```

`txn_date` — в формате `ГГГГММДДЧЧММСС`.

### Ответ: платёж принят

```xml
<?xml version="1.0" encoding="UTF-8"?>
<response>
  <txn_id>123456789</txn_id>
  <prv_txn>1042</prv_txn>
  <sum>10000.00</sum>
  <result>0</result>
  <comment>OK</comment>
</response>
```

`prv_txn` — наш номер операции. По нему разбираются спорные платежи.

### Ответ: счёт не найден

```xml
<response>
  <txn_id>123456789</txn_id>
  <prv_txn>1043</prv_txn>
  <result>1</result>
  <comment>Счёт не найден</comment>
</response>
```

### Ответ: счёт уже оплачен

```xml
<response>
  <txn_id>123456789</txn_id>
  <prv_txn>1044</prv_txn>
  <result>3</result>
  <comment>Счёт уже оплачен</comment>
</response>
```

## 3. Уникальность txn_id — главное

**`txn_id` — ключ идемпотентности.** Обязателен для `pay`.

Повторный `pay` с тем же `txn_id` **не проводит второй платёж**. Мы возвращаем
дословно тот же ответ, что и в первый раз, с тем же `prv_txn`:

```
Первый  вызов: command=pay&txn_id=123456789&account=34906842&sum=10000
                → result 0, prv_txn 1042, подписка продлена

Второй вызов:  тот же txn_id
                → result 0, prv_txn 1042, ничего не начислено повторно
```

Так же обрабатываются и два одновременных запроса с одинаковым `txn_id`:
уникальность обеспечивается на уровне базы, второй запрос получает результат
первого.

Для `check` уникальность `txn_id` не требуется — команда ничего не меняет.
Более того, `check` работает и вовсе без `txn_id`: так удобнее проверять
адрес руками из браузера.

---

## 4. Коды ответа

| `result` | Значение |
|---|---|
| 0 | Успех |
| 1 | Счёт не найден |
| 2 | Счёт отменён или просрочен |
| 3 | Счёт уже оплачен |
| 4 | Платёж в обработке |
| 5 | Прочая ошибка |

---

## 5. Формат ответа

XML по умолчанию. JSON — параметром `format=json`:

```
https://kerektap.kz/api/kaspi/pay?command=check&txn_id=123456789&account=27797236&format=json
```

```json
{
  "txn_id": "123456789",
  "sum": "10000.00",
  "result": 0,
  "comment": "OK",
  "fields": {
    "field1": { "@name": "Исполнитель", "#text": "ТЕСТ Kaspi — не рассылать" },
    "field2": { "@name": "Услуга", "#text": "Подписка на 30 дней" }
  }
}
```

В JSON наш номер операции отдаётся под двумя именами — `prv_txn` и
`prv_txn_id`, — потому что в протоколе XML-пример называет это поле одним
именем, а JSON-пример другим.

## 6. Защита доступа

В протоколе нет ни подписи, ни ключа, поэтому доступ ограничен **списком
IP-адресов**. Запрос с адреса вне списка получает `result 5` и «Доступ
запрещён».

Что нужно от Kaspi:

1. **Полный список IP-адресов**, с которых пойдут запросы, — боевых и
   тестовых. В присланном ранее списке третий адрес отличается от остальных
   (`197` против `194`) — просим подтвердить, что это не опечатка.
2. Готовы дополнительно принимать **постоянное значение в `data1`** как общий
   секрет, если это удобно. Проверка уже реализована и включается настройкой.

---

## 7. Что нужно от Kaspi для запуска

- `service_id` нашей услуги;
- числовые идентификаторы полей для ссылки оплаты;
- IP-адреса тестового и боевого контуров;
- подтверждение по комиссии 1,5%: удерживается из суммы платежа или
  начисляется сверх неё.

## 8. Тестовые счета

Специально для проверки заведены два счёта, оба действуют до 8 ноября 2026:

| Номер | Для чего |
|---|---|
| `27797236` | для `check` — остаётся неоплаченным, отвечает кодом 0 сколько угодно раз |
| `34906842` | для `pay` — по нему можно провести один тестовый платёж |

Сумма по обоим — 10 000 ₸, период 30 дней. Оба принадлежат служебному
профилю «ТЕСТ Kaspi», который не участвует в работе сервиса.

## 9. Проверка прямо сейчас

Адрес отвечает уже сегодня. До того как вы пришлёте боевые IP, запросы с
чужих адресов отклоняются — это ожидаемое поведение, а не ошибка.

Для диагностики есть отдельный адрес, показывающий, каким мы видим адрес
звонящего:

```
https://kerektap.kz/api/kaspi/whoami
```

Пришлите его вывод со своей стороны — сразу станет видно, тот ли IP нужно
вносить в список.
